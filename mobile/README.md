# SmartSpend mobile

The Flutter app for Android and iOS. Why it is built this way, what is decided and what comes next:
[docs/decisions/0022-flutter-mobile-app.md](../docs/decisions/0022-flutter-mobile-app.md). Rules for changing it:
[AGENTS.md](AGENTS.md).

## Layout
A Dart pub workspace: one `flutter pub get` here resolves every package into one `pubspec.lock`.

| Folder | Package | What it holds |
| --- | --- | --- |
| `app/` | `smartspend_app` | The application: configuration, routes, screens, Riverpod providers, Arabic and English texts, and the Android and iOS projects |
| `packages/smartspend_api/` | `smartspend_api` | Pure Dart. `TrpcClient` calls the API over HTTP; `Procedures` lists every procedure a user may call, generated from `api/router.ts` |
| `packages/smartspend_ui/` | `smartspend_ui` | The design system: colours, spacing and type tokens, the light and dark themes, the bottom bar, the bottom sheet, the Cairo font |
| `packages/bank_capture/` | `bank_capture` | A Flutter plugin: the Android notification listener in Kotlin and the iOS side in Swift, behind a Dart API generated by Pigeon |

Inside `app/lib/src/`: `config/` (build settings), `core/` (providers, session storage), `routing/` (the five tabs
and the shell), `features/<feature>/` (screens), `l10n/` (texts).

## Setting up
1. Install exactly the Flutter release named under `environment.flutter` in [pubspec.yaml](pubspec.yaml), and put its
   `bin` folder on `PATH`. `flutter pub get` refuses any other version, so every machine and CI build the same app.
2. Android builds need JDK 17 and the Android SDK (Android Studio installs both). iOS builds need a Mac with Xcode.
   Without them you can still analyze and test everything here.
3. From this folder: `flutter pub get`.

## Running against your API
Start the API from the repository root with `npm run dev` (port 3000), then:

```bash
cd app
flutter run --dart-define-from-file=config/development.json
```

A debug build calls `http://10.0.2.2:3000` from the Android emulator and `http://localhost:3000` from the iOS
simulator. On a real phone, add `--dart-define=SMARTSPEND_API_URL=http://<your computer's LAN address>:3000`. A
release build must be given an `https://` address and refuses to start without one. Debug builds install as
`com.smartspend.app.dev` ("SmartSpend Dev"), next to a store build.

## Checking a change
From this folder, the same steps CI runs (`.github/workflows/mobile.yml`):

```bash
flutter pub get
dart format .
flutter analyze
```

Tests, per package: `dart test` in `packages/smartspend_api`, `flutter test` in the other three.

## Seeing the app without a phone or a Mac
`.github/workflows/mobile-screenshots.yml` runs the app on an Android emulator and an iOS simulator on GitHub's
machines and photographs every tab in the dark and light themes (`app/integration_test/screenshots_test.dart`). After
a change reaches `main`, the pictures are on the
[mobile-screenshots branch](https://github.com/mahmoudtaherr111/smartspend_mini_all/tree/mobile-screenshots), whose
README shows them side by side; on other branches they are artifacts of the run. A new screen belongs in that test,
so its picture appears there too. With a device or simulator of your own:

```bash
cd app
flutter drive --driver=test_driver/integration_test.dart --target=integration_test/screenshots_test.dart
```

## Generated code
| File | Made by | When |
| --- | --- | --- |
| `packages/smartspend_api/lib/src/generated/procedures.g.dart` | `npm run atlas` at the repository root | A tRPC procedure is added, renamed or removed. The git hooks and `npm run agent:finish` regenerate it; never edit it |
| `packages/bank_capture/lib/src/bank_capture_api.g.dart`, `BankCaptureApi.g.kt`, `BankCaptureApi.g.swift` | Pigeon, from `packages/bank_capture/pigeons/bank_capture_api.dart` | You change that file; the command is at its top |
| `app/lib/src/l10n/app_localizations*.dart` | `flutter pub get` (gen-l10n, `app/l10n.yaml`) | You change an `.arb` file |

## Calling the API
```dart
final client = ref.read(trpcClientProvider);
final data = await client.query(Procedures.expense.list, input: {'limit': 20});
```

`query` takes only queries and `mutate` only mutations, so the HTTP method is always right. Errors arrive as
`ApiException`, whose `message` is the server's Egyptian Arabic text and safe to show, or as `ApiNetworkException`
when there was no answer.
