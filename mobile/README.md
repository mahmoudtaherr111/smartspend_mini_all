# SmartSpend mobile

The Flutter app for Android and iOS. Why it is built this way, what is decided and what comes next:
[docs/decisions/0022-flutter-mobile-app.md](../docs/decisions/0022-flutter-mobile-app.md). Rules for changing it:
[AGENTS.md](AGENTS.md).

## Layout
A Dart pub workspace: one `flutter pub get` here resolves every package into one `pubspec.lock`.

| Folder | Package | What it holds |
| --- | --- | --- |
| `app/` | `smartspend_app` | The application: configuration, routes, screens, Riverpod providers, Arabic and English texts, and the Android and iOS projects |
| `packages/smartspend_api/` | `smartspend_api` | Pure Dart. `TrpcClient` calls the API over HTTP; `Procedures` lists every procedure a user may call, generated from `api/router.ts` |
| `packages/smartspend_ui/` | `smartspend_ui` | The design system: tokens, the light and dark themes, the Cairo font, and the components screens are built from (buttons, transaction rows, money, empty, error, loading and offline states, notices with undo, haptics, motion); `gallery.dart` shows them all |
| `packages/bank_capture/` | `bank_capture` | A Flutter plugin: the Android notification listener in Kotlin and the iOS side in Swift, behind a Dart API generated by Pigeon |
| `packages/device_lock/` | `device_lock` | A Flutter plugin for the app lock: biometrics bound to a Keystore or Keychain key, the key that tags the PIN, and the cover in the app switcher (decision 0023) |

Inside `app/lib/src/`: `config/` (build settings), `core/` (providers, session storage), `routing/` (the five tabs,
the shell and the route guard), `features/<feature>/` (screens; `features/auth/` is sign-in, sign-up and the session),
`l10n/` (texts).

## Setting up
1. Install exactly the Flutter release named under `environment.flutter` in [pubspec.yaml](pubspec.yaml), and put its
   `bin` folder on `PATH`. `flutter pub get` refuses any other version, so every machine and CI build the same app.
2. Android builds need JDK 17 and the Android SDK (Android Studio installs both). iOS builds need a Mac with Xcode.
   Without them you can still analyze and test everything here.
3. From this folder: `flutter pub get`.

## Running against your API
Start the API from the repository root with `npm run dev` (port 3000), then:

```bash
cd app
flutter run --dart-define-from-file=config/development.json
```

A debug build calls `http://10.0.2.2:3000` from the Android emulator and `http://localhost:3000` from the iOS
simulator. On a real phone, add `--dart-define=SMARTSPEND_API_URL=http://<your computer's LAN address>:3000`. A
release build must be given an `https://` address and refuses to start without one. Debug builds install as
`com.smartspend.app.dev` ("SmartSpend Dev"), next to a store build.

### Signing in
Phone numbers work with no setting. Two more are optional dart-defines, public identifiers rather than secrets:

| Define | What it turns on |
| --- | --- |
| `GOOGLE_SERVER_CLIENT_ID` | The Google button: the server's web client id (`GOOGLE_CLIENT_ID` on the server). On iOS also `GOOGLE_IOS_CLIENT_ID`, with that id reversed as `GOOGLE_REVERSED_CLIENT_ID` in `app/ios/Flutter/GoogleSignIn.xcconfig`. The server accepts the tokens only when `GOOGLE_ANDROID_CLIENT_IDS` or `GOOGLE_IOS_CLIENT_IDS` names this build's client |
| `TURNSTILE_SITE_KEY` | The "not a robot" check before a WhatsApp code, as the website's `VITE_TURNSTILE_SITE_KEY`. Cloudflare must list the API's host for the key. A development server accepts sign-ups without it |

The Android client in Google Cloud is matched by package name and signing key: `com.smartspend.app.dev` with the
debug key for a debug build. How the server checks the token: "Google, in the mobile app" in
[docs/systems/accounts.md](../docs/systems/accounts.md).


## Seeing the app without a phone or a Mac
`.github/workflows/mobile-screenshots.yml` runs the app on an Android emulator and an iOS simulator on GitHub's
machines and photographs every tab in the dark and light themes (`app/integration_test/screenshots_test.dart`). After
a change reaches `main`, the pictures are on the
[mobile-screenshots branch](https://github.com/mahmoudtaherr111/smartspend_mini_all/tree/mobile-screenshots), whose
README shows them side by side; on other branches they are artifacts of the run. A new screen belongs in that test,
so its picture appears there too. With a device or simulator of your own:

```bash
cd app
flutter drive --driver=test_driver/integration_test.dart --target=integration_test/screenshots_test.dart
```

## Calling the API
```dart
final client = ref.read(trpcClientProvider);
final data = await client.query(Procedures.expense.list, input: {'limit': 20});
```

`query` takes only queries and `mutate` only mutations, so the HTTP method is always right. Errors arrive as
`ApiException`, whose `message` is the server's Egyptian Arabic text and safe to show, or as `ApiNetworkException`
when there was no answer. A call that carried the session token and is refused as `UNAUTHORIZED` ends the session
(`onSessionRejected`, wired in `app/lib/src/core/providers.dart`): the token is forgotten and the router shows sign-in.

The app calls no route outside tRPC except the capture routes under `/api/capture/v1`, used by native code.

## Architecture Patterns (Repositories, Caching, and UI)

Session 1 established the canonical patterns that all subsequent mobile sessions follow:

### 1. Repository & Caching Pattern (FND-06)
- **Account-Scoped Cache**: Repositories cache their last good response in `StoredLedger` / `LocalLedger` scoped to the current user key (`${user.kind.name}:${user.id}`).
- **Stale-While-Revalidate**: Cached answers display immediately while network requests refresh in the background, eliminating blank screen flashes.
- **Refresh Error Retention (FND-06)**: Pull-to-refresh (`RefreshIndicator`) never wipes the screen when the server returns a 500 or network error. Screens inspect `asyncValue.value`: if cached data exists, it continues rendering the content instead of switching to `ErrorState`. The refresh handler catches the error and surfaces `showSmartSpendNotice(context, l10n.refreshFailedNotice)` ("ماقدرناش نحدّث البيانات دلوقتي. البيانات المعروضة هي آخر نسخة محفوظة."). Initial loads with no cached data still present `ErrorState` with a retry button.
- **Graceful Offline Fallback & Partial States (MON-03)**: On `ApiNetworkException`, `networkStatusProvider.unreachable()` flags the offline state, and the repository serves cached data instead of blowing up. When opening detailed views (such as a wallet) offline without cached transactions, known figures (like balance and sync date) are shown with a partial notice (`l10n.walletOfflinePartial`) naming what is missing rather than a generic error.
- **Multi-Tenant Isolation**: Signing out (`SessionController.signOut()`) or switching accounts completely wipes the local store (`localLedger.wipe()`), app lock credentials (`appLock.wipe()`), and outbox to prevent data leakage between different users on the same phone.
- **Single Offline Banner**: A screen shows one top-level banner when offline via `networkStatusProvider`, never an offline indicator per card.

### 2. Mutation & Invalidation Pattern (REC-07, REC-08)
- **Coordinated Refresh**: After any ledger write (create, edit, delete, undo), calling `refreshLedger(ref)` or `invalidateLedgerContainer(container)` invalidates all dependent providers across tabs (month summary, recent entries, paginated list, stats, and wallet summaries) without full page reload.
- **Offline Edit Safety**: Edits (`showEditTransactionSheet`) require connectivity and are disabled when offline with a clear explanation (`l10n.transactionEditOffline`), because edits are not queued in the outbox.
- **Timezone Consistency**: Editing dates uses UTC noon (`DateTime.utc(year, month, day, 12, 0, 0)`) so that transactions near midnight never cross Cairo business calendar day boundaries (golden rule 6). Unchanged dates omit the date field to preserve exact server timestamps.
- **Friendly Fallbacks**: Missing entities (such as a deleted wallet or unlinked contact) always show localized labels (`l10n.transactionWalletUnknown`, `l10n.transactionPersonUnknown`), never raw database IDs (`#id`).

### 3. Motion & Screen Navigation (FND-05, FND-09)
- **Shared-Element Transitions**: Transaction rows open `TransactionDetailScreen` with a Hero animation of both category icon and amount using `smartSpendHeroShuttle` on transparent Material.
- **Session-Scoped Staggered Reveal**: `StaggeredReveal` animates card entrances only once per session (`sessionKey`) to prevent repetitive motion on every tab switch, and collapses to instant display under reduced motion (`SmartSpendMotion.enabledOf(context)`).
- **Predictive Back**: Android predictive back (`enableOnBackInvokedCallback="true"`) and Cupertino edge-swipe are configured to dismiss sheets and navigate cleanly.

### 4. Sheet & Form Pattern (FND-09)
- **Draft & Edit Protection**: Modal sheets and creation forms (such as `_EditTransactionSheet` and `_WalletForm`) track their dirty state by attaching listeners to text controllers and comparing against initial values. If the user attempts to swipe down, press Android back, or tap cancel while dirty, `PopScope` intercepts the dismissal and presents a confirmation dialog (`l10n.discardChangesTitle` / `l10n.discardChangesBody`), preventing silent loss of edits.
