# دليل SmartSpend لصاحب المشروع

الدليل ده بيشرح إزاي تشوف المشروع كخريطة، وإزاي الـagents بتفضل ماشية على الحقيقة من غير ما حد يحدّث
المستندات بإيده، وإزاي تعرف إيه اللي اتغير. المستندات اللي بتقرأها الـagents مكتوبة بالإنجليزي، والدليل ده
ليك إنت.

## الفكرة في 4 طبقات
1. **شرح الأنظمة** في `docs/systems/` (إنجليزي) و`docs/ar/systems/` (عربي): التطبيق مقسوم لأجزاء، كل جزء
   بنسميه «نظام»، وكل نظام ليه صفحة بتقول بيعمل إيه، وبيشتغل إزاي، وإيه مشاكله المعروفة. دي أول حاجة تتقري،
   وأول حاجة تدّيها للـagent لما تطلب تعديل. الفهرس بالعربي في
   [`docs/ar/systems/README.md`](systems/README.md).
2. **حقائق متولّدة من الكود** في `docs/atlas/`: الـprocedures والجداول والـroutes والـjobs والصفحات
   والموديولات ومتغيرات البيئة. محدش بيكتبها بإيده؛ الأمر `npm run atlas` بيقرأ الكود ويكتبها من جديد.
3. **خريطة LikeC4** في `docs/architecture/`. الجزء المتولّد منها في `docs/architecture/generated/`، وجنبه
   ملفات مكتوبة بإيد: السياق، والـviews، ومسارات السير، ووصف كل موديول في `docs/architecture/clusters.json`.
4. **قواعد قصيرة للـagents** في `AGENTS.md`، ونسخة لكل فولدر في `api/` و`api/lib/` و`src/` و`db/`. كل قاعدة
   ليها فحص في `scripts/knowledge/` بيفشل لو القاعدة اتكسرت، ولو مفيش فحص مكتوب جنبها `unenforced`.

## إزاي كل ده بيتحدث لوحده
مفيش حد محتاج يكتب "أنا غيرت كذا". التحديث بيحصل تلقائي في كل لحظة الشغل بيتنقل فيها:

| إمتى | إيه اللي بيحصل |
| --- | --- |
| Claude Code أو Codex يبدأ جلسة | الـagent يعرف فرعه متأخر عن `main` بكام commit وإيه اللي فاته، ويفتكر خطوات الشغل |
| الـagent يخلّص دوره | الأطلس يتولّد من جديد والقواعد تتفحص؛ لو قاعدة اتكسرت يرجع يصلحها قبل ما يقول خلصت |
| أي حد يعمل commit | الأطلس الجديد يدخل في نفس الـcommit، ويتسجل في آخر الرسالة سطر `Agent:` باسم الأداة |
| merge أو pull | الملفات المتولّدة ماتعملش conflict؛ بتتولّد من جديد للكود المدموج وتتسجل |
| push | لو قاعدة مكسورة، الـpush يترفض برسالة بتقول تتصلح إزاي |
| الكود يوصل `main` على GitHub | الـCI يولّد الأطلس لو ناقص ويعمله commit، ويكتب ملخص عربي باللي اتغير |
| الـagent يغيّر كود موصوف في صفحة نظام | الفحص بيقوله «الصفحة دي بقت قديمة»، وماينفعش يرفع قبل ما يقراها ويصلحها ويسجلها بـ`npm run docs:verify` |

الشرح الهندسي لكل خطوة في `docs/guides/agent-workflow.md`.

## الـagents كلها على نفس النسخة
كل agent بيشتغل في فرعه. عشان محدش يبني على نسخة قديمة:
1. أول كل مهمة: `npm run sync` بيجيب آخر `main` ويدمجه في الفرع.
2. آخر كل مهمة: `npm run agent:finish`، وبعدين commit.
3. بعدها `npm run ship`: بيدمج آخر `main` تاني ويرفع الشغل على `main` نفسه، ولو حد رفع حاجة في النص
   بيدمجها ويرفع تاني. كده كل الـagents بيبنوا على نفس النسخة.
4. الشغل يتسلّم على خطوات صغيرة في نفس اليوم؛ الفرع اللي بيعيش أيام بيجمّع conflicts.

## تعرف إحنا فين إزاي
- [`docs/atlas/systems/state.ar.md`](../atlas/systems/state.ar.md): صفحة واحدة متولّدة لوحدها فيها كل نظام،
  وآخر مراجعة لشرحه، وعدد اختباراته، وكل المشاكل المعروفة في المشروع مجمّعة. دي أقرب حاجة لـ«لوحة حالة» للمشروع.
- `npm run who`: مين شغال دلوقتي في المشروع (أي أداة، أي فرع، وأنهي ملفات)، ولو حد بيعدّل نفس الملفات اللي
  إنت فيها. مفيش حد بيسجّل حاجة بإيده؛ الكلام كله متقري من git.

## تعرف إيه اللي اتغير إزاي
- الأمر `npm run changes -- --lang ar` بيطلع تقرير عربي بآخر أسبوع: كل commit ومين عمله (Codex ولا Claude
  ولا غيرهم)، وإيه اللي اتضاف أو اتشال من جداول وAPIs وصفحات ومهام وخدمات خارجية، ومين بقى بيقرأ أو بيكتب
  في إيه.
- نفس التقرير بيتكتب لوحده في صفحة تشغيل الـCI على GitHub مع كل push على `main`.
- التقرير متولّد من git ومن الخريطة المتولّدة، فمش ممكن يكدب أو ينسى تغيير في شكل النظام. التغييرات اللي
  جوه كود موجود من غير ما تغيّر شكل النظام بتبان في قايمة الـcommits بس.

## تشوف الخريطة إزاي
- مرة واحدة بس: `npm run arch:install`.
- بعدها `npm run arch`، وافتح الرابط اللي هيظهر. تقدر تبحث، وتكبّر، وتدوس على أي عنصر تدخل جواه.
- لو عايز ملف HTML واحد تبعته لحد أو تفتحه من غير سيرفر:
  `npm run arch:build -- --output-single-file`.

## كل view بتوريك إيه
| الـview | بتوريك |
| --- | --- |
| `index` | الناس والتطبيقات اللي حوالين النظام، والخدمات الخارجية (Gemini وPaymob وWhatsApp وغيرها) |
| `containers` | الواجهة والـAPI وقاعدة البيانات والـstores |
| `api` | جوه السيرفر: الـrouters والـroutes والـWebSocket والـjobs والموديولات |
| `web` | صفحات الواجهة وهي بتنادي أنهي procedures |
| `server_modules` | موديولات السيرفر، كل موديول بيعمل إيه، ومين بيعتمد على مين |
| `database` | الجداول |
| `who_touches_expenses` | كل حاجة بتقرأ أو بتكتب في جدول المصاريف |
| `flow_record_expense` | تسجيل مصروف من جملة مكتوبة |
| `flow_sms_ingest` | رسالة بنك أو محفظة جاية من الموبايل |
| `flow_ai_chat` | سؤال في AI Center |
| `flow_paymob_upgrade` | ترقية الباقة عن طريق Paymob |
| `router_*` و`module_*` | view لكل router ولكل موديول لوحده |

مسارات السير (flows) مرسومة بإيد، بس الفحص في `scripts/knowledge/flows-rules.ts` بيتأكد إن كل خطوة فيها ليها
علاقة حقيقية في الكود. يعني لو حد غيّر الكود والمسار بقى غلط، الفحص هيفشل. الوصف المكتوب جنب كل مسار أو
موديول اتراجع على الكود وقت كتابته، والفحص مابيقدرش يتأكد من معنى الجملة، فلازم يتحدث مع أي تغيير في
اللي بيوصفه.

## تسأل الـagent إزاي
أول خطوة دايماً: قوله يقرا صفحة النظام المناسبة من [`docs/ar/systems/README.md`](systems/README.md) أو من
`docs/systems/`. بعد كده يقدر يسأل الخريطة مباشرة عن طريق MCP (السيرفر `likec4` في `.mcp.json`).
أمثلة لأسئلة تقدر تطلبها منه:
- "مين بيكتب في جدول `expenses`؟"
- "لما حد يبعت SMS من الموبايل، الطلب بيعدي على إيه لحد ما يتسجل؟"
- "الـprocedure `chat.sendMessage` بتستخدم أنهي موديولات وجداول؟"
- "أنهي procedures مالهاش أي استخدام من الواجهة؟"
- "لو غيرت جدول `user_contacts`، مين هيتأثر؟"
- "إيه اللي اتغير في النظام الأسبوع ده، ومين غيّره؟"

## لما تطلب تغيير
قول للـagent يمشي على "Working protocol" و"Definition of done" اللي في `AGENTS.md`. باختصار: `npm run sync` في
الأول، و`npm run agent:finish` في الآخر، والكود والملفات المتولّدة في نفس الـcommit، و`npm run ship` في نفس
اليوم عشان الشغل يوصل `main`.

## تحذيرات مهمة دلوقتي
- أخطاء الـlint القديمة متسجلة في `eslint-suppressions.json`: أي خطأ جديد بيفشّل الفحص، والقديم بيقل كل ما حد
  يصلّح حاجة منه.
- المهام المجدولة (انتهاء الاشتراكات، التقارير الشهرية، تنظيف البيانات القديمة) مابتشتغلش غير لو `ENABLE_CRONS`
  قيمته `true`، والقيمة في `.env.example` هي `false`. خطوات النشر كلها في `docs/guides/deploy.md`.
- Codex مش هيشغّل الـhooks بتاعته غير لما تعلّم المشروع إنه موثوق (trusted) جوه Codex.

## قاموس صغير
| الكلمة | معناها هنا |
| --- | --- |
| atlas | الحقائق المتولّدة من الكود |
| procedure | دالة في الـAPI بتناديها الواجهة |
| router | مجموعة procedures في ملف واحد |
| module أو cluster | مجموعة ملفات شغلانتها واحدة |
| flow | مسار سير مرسوم خطوة بخطوة |
| view | منظر من الخريطة |
| MCP | الطريقة اللي الـagent بيسأل بيها الخريطة |
| drift | لما المستند يبعد عن الكود |
| hook | أمر بيشتغل لوحده في لحظة معينة: بداية جلسة، commit، merge، push |
| sync | إن فرعك ياخد آخر نسخة من `main` |
| trailer | سطر في آخر رسالة الـcommit، زي `Agent: codex`، بيقول مين عمل التغيير |
