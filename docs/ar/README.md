# دليل SmartSpend لصاحب المشروع

الدليل ده بيشرح إزاي تشوف المشروع كخريطة، وإزاي الـagents بتفضل ماشية على الحقيقة، ولما تطلب تغيير
تطلبه إزاي. المستندات اللي بتقرأها الـagents مكتوبة بالإنجليزي، والدليل ده ليك إنت.

## الفكرة في 3 طبقات
1. **حقائق متولّدة من الكود** في `docs/atlas/`. فيها الـprocedures والجداول والـroutes والـjobs والصفحات
   ومتغيرات البيئة. محدش بيكتبها بإيده: الأمر `npm run atlas` بيقرأ الكود ويكتبها من جديد.
2. **خريطة LikeC4** في `docs/architecture/`. الجزء المتولّد منها في `generated/`، وجنبه ملفات مكتوبة بإيد:
   الأنواع والسياق والـviews ومسارات السير.
3. **قواعد قصيرة للـagents** في `AGENTS.md`، ونسخة لكل فولدر في `api/` و`api/lib/` و`src/` و`db/`.
   كل قاعدة مكتوب جنبها الفحص اللي بيتأكد منها، ولو مفيش فحص مكتوب `unenforced`.

الفحص `npm run atlas:check` جزء من `npm run check` ومن الـCI. أول ما الكود يتغير والحقائق ماتتحدثش
بيفشل، ومعاه اسم الملف القديم.

## تشوف الخريطة إزاي
- مرة واحدة بس: `npm run arch:install`.
- بعدها `npm run arch`، وافتح الرابط اللي هيظهر. تقدر تبحث، وتكبّر، وتدوس على أي عنصر تدخل جواه.
- لو عايز ملف HTML واحد تبعته لحد أو تفتحه من غير سيرفر:
  `npm run arch:build -- --output-single-file`.

## كل view بتوريك إيه
| الـview | بتوريك |
| --- | --- |
| `index` | الناس والتطبيقات اللي حوالين النظام، والخدمات الخارجية (Gemini وPaymob وWhatsApp وغيرها) |
| `containers` | الواجهة والـAPI وقاعدة البيانات والـstores |
| `api` | جوه السيرفر: الـrouters والـroutes والـWebSocket والـjobs والموديولات |
| `web` | صفحات الواجهة وهي بتنادي أنهي procedures |
| `server_modules` | موديولات السيرفر ومين بيعتمد على مين |
| `database` | الجداول |
| `who_touches_expenses` | كل حاجة بتقرأ أو بتكتب في جدول المصاريف |
| `flow_record_expense` | تسجيل مصروف من جملة مكتوبة |
| `flow_sms_ingest` | رسالة بنك جاية من الموبايل |
| `flow_ai_chat` | سؤال في AI Center |
| `flow_paymob_upgrade` | ترقية الباقة عن طريق Paymob |
| `router_*` و`module_*` | view لكل router ولكل موديول لوحده |

مسارات السير (flows) مرسومة بإيد، بس الاختبار `tests/knowledge/flows.test.ts` بيتأكد إن كل خطوة فيها ليها
علاقة حقيقية في الكود. يعني لو حد غيّر الكود والمسار بقى غلط، الاختبار هيفشل.

## تسأل الـagent إزاي
الـagent اللي شغال في المشروع يقدر يسأل الخريطة مباشرة عن طريق MCP (السيرفر `likec4` في `.mcp.json`).
أمثلة لأسئلة تقدر تطلبها منه:
- "مين بيكتب في جدول `expenses`؟"
- "لما حد يبعت SMS من الموبايل، الطلب بيعدي على إيه لحد ما يتسجل؟"
- "الـprocedure `chat.sendMessage` بتستخدم أنهي موديولات وجداول؟"
- "أنهي procedures مالهاش أي استخدام من الواجهة؟"
- "لو غيرت جدول `user_contacts`، مين هيتأثر؟"

## لما تطلب تغيير
قول للـagent يلتزم بـ Definition of Done اللي في آخر `AGENTS.md`. باختصار:
1. `npm run check` يعدّي، واختبارات الملفات اللي اتغيرت تعدّي.
2. لو غيّر router أو جدول أو route أو صفحة، يشغّل `npm run atlas` ويعمل commit للملفات المتولّدة مع التغيير.
3. لو غيّر مسار مرسوم في `docs/architecture/flows/`، يحدّث المسار.
4. ماتتحطش خطط ولا ملخصات جلسات جوه `docs/`.

## تحذيرات مهمة دلوقتي
- الأمر `npm run test` كامل بيعمل commit لكل التعديلات اللي لسه ماتحفظتش، بسبب `tests/unlock.test.ts`.
  لحد ما الاختبار ده يتصلح، شغّل اختبارات محددة بس: `npx vitest run <path>`.
- `npm run check` بيفشل دلوقتي بسبب أخطاء types قديمة في ملفات البروفايل وصفحة الأدمن، مش بسبب الخريطة.

## قاموس صغير
| الكلمة | معناها هنا |
| --- | --- |
| atlas | الحقائق المتولّدة من الكود |
| procedure | دالة في الـAPI بتناديها الواجهة |
| router | مجموعة procedures في ملف واحد |
| module أو cluster | مجموعة ملفات شغلانتها واحدة |
| flow | مسار سير مرسوم خطوة بخطوة |
| view | منظر من الخريطة |
| MCP | الطريقة اللي الـagent بيسأل بيها الخريطة |
| drift | لما المستند يبعد عن الكود |
