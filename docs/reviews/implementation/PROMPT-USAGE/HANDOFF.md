المخرجات الغامضة أو المتناقضة تحمل مانع مراجعة ثابتاً؛ لا تمحو طبقة لاحقة هذا المانع. الفرعيات المخترعة لا تمر بصمت. الاختبارات تثبت الفصل البنيوي للنصوص الخبيثة وثبات الموانع، ولا تثبت أن JSON يمنع كل prompt injection لدى نموذج فعلي.

## الكاش: آليتان مختلفتان

1. **Result cache داخل التطبيق:** لا استدعاء ولا توكنز جديدة. `tokensUsed=0` و`cachedTokens=0`؛ `resultCacheSavedTokens` منفصل ويشير إلى استهلاك التنفيذ الأصلي، وليس خصماً مقاساً على فاتورة جديدة. المفتاح يشمل المستخدم ونوعه وخطته ونطاق العمل والنموذج والعتبات ونسخة المعايرة، ويضيف hash التعليمات/schema والسياق والقواميس والتصحيحات ومسارات الأدمن واليوم المحلي والإعدادات وحد المخرجات وسياسة الاستيضاح. إبطال الكاش بتصحيح المستخدم محفوظ. لا تخزين لفشل المزوّد أو الرد غير الصحيح أو ambiguous/conflict لمدة أسبوع.
2. **Prompt cache لدى المزوّد:** يحافظ البرومبت على system prefix ثابت ويضع البيانات المتغيرة بعده. الـhit يخضع للموديل والمزوّد وطول المقدمة وعمر الكاش والتوجيه؛ ليس مضموناً وليس مجانياً بالضرورة. لم نضف حشواً لبلوغ حد الكاش، ولم ننشئ explicit caches لها تكلفة تخزين. الكاش المحلي ما زال داخل العملية؛ لا Redis cache موزع أو single-flight جديد في هذه الحزمة.

لم نغيّر model mapping أو نثبت اسماً لنموذج. OpenRouter يستفيد من مسار OpenAI-compatible إذا أُعدّ في الأدمن؛ لا تدّعي هذه الحزمة إنشاء حسابه أو تفعيل أي نموذج بعينه.

## المحاسبة ولوحة الأدمن

`api/lib/provider-usage.ts` يطبّع حقول Gemini، DeepSeek المباشر، OpenAI-compatible/OpenRouter، وحقول Fireworks في headers. توجد تغطية لوحدات Anthropic الأصلية في المساعد، لكن ذلك لا يعني إضافة بروتوكول Anthropic الأصلي إلى الراوتر.

- Input يتضمن cache hit؛ لا يُجمع الكاش مرة ثانية. Gemini thoughts يضاف مرة واحدة إلى Output، وreasoning في OpenAI-compatible جزء من Output بالفعل.
- cache reads وcache writes مستقلان. القيم الناقصة تبقى null؛ عدم وجود القياس لا يتحول إلى ادعاء استهلاك صفري.
- تكلفة المزوّد المبلّغ عنها، ومنها `usage.cost` في OpenRouter، لها الأولوية. وإلا يُحسب تقدير بأسعار المسار الفعلي المحفوظة في الأدمن، مع snapshot للأسعار. أسعار cache writes الناقصة تمنع اختلاق تكلفة لها. لا أسعار موحدة ولا سعر صرف ثابت.
- أسعار `ai_models` قد تكون افتراضية أو قديمة؛ تسمية «تقدير بأسعار الأدمن» مقصودة. مطابقة الفاتورة تحتاج مراجعة هذه الإعدادات، ولا يثبت وجود قيمة في الجدول صحتها التجارية.
- كل محاولة مدفوعة تُسجل مستقلة، بما فيها الرد المقطوع أو الفارغ؛ الفشل بدون usage يسجل قياساً غير متاح. operationId يجمع المحاولات، ويظهر كذلك في parser trace. أُزيل سجل التصنيف المكرر من trackTokens مع إبقاء عدادات الحصة الحالية.
- تخفيض schema لا يعيد ميزانية المهلة من بدايتها؛ زمن كل محاولة يُقاس مستقلاً. لا شبكة في اختبارات ذلك.
- سجلات التصنيف الجديدة لا تحتوي نص المصروف أو قائمة الأشخاص أو مفاتيح API. هذا لا ينظف بأثر رجعي كل logs التطبيق القديمة.
- الأعمدة القديمة غير القابلة لـnull تحتفظ بأصفار تقنية؛ `metadata.accounting` هو المرجع للقيم المفقودة. الواجهة والمجاميع المحدثة تستخدم هذا التمييز. لا ترحيل للقياسات التاريخية المختلقة.
- نسبة كاش الأدمن تستخدم فقط Input وCache المقاسين معاً، وتعرض مقام القياس. ليست نسبة توفير مالي. الصفوف تعرض الموديل والمزوّد والمحاولة وInput/Output/Cache hit/Cache write والتكلفة ومصدرها.
- نافذة التشريح لا تفترض أن الأجزاء غير المقاسة تساوي صفراً أو أن بقية البرومبت كلها Output.

حفظ السجل ينتظر حتى 250ms، ثم تستمر محاولة الإدخال نفسها دون retry؛ عدد الإدخالات المعلقة محدود بـ64. الفشل أو امتلاء الانتظار يُصدر تحذيراً عاماً. هذه محاسبة تشغيلية محدودة الانتظار، **وليست durable billing outbox**: تعطل DB أو توقف العملية قد يفقد قياسات. يلزم outbox وتسوية مع المزوّد إذا أصبح السجل مرجع الفوترة الملزم.

المغطى هنا هو **LLM تصنيف المصروفات عبر هذه المسارات وكل مزوّديها**. قنوات STT/OCR/chat القديمة التي لا تعيد usage موحداً تظهر قياساتها غير متاحة؛ لم ندّع اكتمال قياس جميع منتجات AI الأخرى. توحيد تلك القنوات خطوة منفصلة تستعمل نفس العقد.
