## 3. R1 — دورة حياة التقرير

**قبل:** الناتج الافتراضي مسار **متتبَّع** داخل حزمة التسليم، والـupload بـ`if: always()`.
محاولة حمراء تستطيع نشر artifact باسمها يحمل أرقام محاولة سابقة. المراجعة أثبتته:
التقرير القديم بقي بنفس الـhash وبتوقيت `2026-09-05T14:30:48.231Z` بعد فشل البوابة.

**بعد**، وكل تغيير يعمل عملًا مختلفًا:

1. **الناتج الافتراضي `.artifacts/classification-core/report-<runId>-<attempt>.json`** — غير متتبَّع
   (`.gitignore`)، فلا شيء في المستودع لـcheckout أن يبعثه.
2. **`status`, `git.commit`, `git.tree`, `git.dirty`, `ci.runId`, `ci.attempt`** داخل التقرير.
   artifact لا يخص هذه المحاولة صار يقول ذلك بنفسه.
3. **عند الفشل يُكتب ملف `status: "failed"`** يحمل المرحلة و**صفر مقاييس**، ويُحذف أي ملف نجاح
   قديم على نفس المسار. الامتناع عن الكتابة هو ما جعل الملف القديم يمرّ كالجديد.
4. **الكتابة ذرية** — ملف مؤقت ثم `rename`. عملية تُقتل أثناء الكتابة تترك السابق أو لا شيء،
   لا نصف مستند JSON يقرأه التالي كحقيقة.

### الإثبات

| السيناريو | النتيجة |
| :-- | :-- |
| تقرير **نجاح** قديم على المسار + فشل البوابة | exit 1؛ الملف صار `status: failed`, `failedStage: quality-gate`, **بلا `headline`** |
| فشل بدء العملية | exit 1، `failedStage: spawn` |
| baseline غير صالح | exit 2، `failedStage: contract` |
| نجاح | exit 0، تقرير كامل بـ`status: success` |

الـCI الآن يرفع `classification-core-report-${run_id}-${run_attempt}`، و`if: always()` صار
**آمنًا** لأن الملف الموجود عند الفشل هو تشخيص بلا أرقام.

### عيب وجده حارسي أثناء كتابته

`api/lib/e2e-classification.test.ts` يقرأ **`process.env.FIREWORKS_API_KEY`** ويمرّره إلى
`matchSegment`. و`vitest.config.ts` ينادي `dotenv.config()`. أي أن السويت «offline» كانت
**ستُجري استدعاءً مدفوعًا على أي جهاز فيه مفتاح حقيقي** — وهذا الملف كان داخل قائمة G1 الأصلية أيضًا.

لم أعدّل الملف (المراجعة والبرومبت يمنعان إضعاف اختبار)، وملاحقة كل ملف هي الرافعة الخطأ:
أي ملف قد يقرأ مفتاحًا لسبب مشروع. **الأمر نفسه يضمن القيمة الآن:**

```
cross-env FIREWORKS_API_KEY= GEMINI_API_KEY= GROQ_API_KEY= NVIDIA_API_KEY= \
          DEEPSEEK_API_KEY= OPENAI_API_KEY= OPENROUTER_API_KEY= vitest run …
```

كون التشغيل offline صار **خاصية طريقة الاستدعاء**، لا وعدًا على كل ملف أن يحفظه.
واختبار يسجّل الملفات القارئة للمفاتيح صراحةً، فظهور ملف جديد يستدعي قرارًا.

### 5.2 القابلية للمقارنة (R4)

`evaluationFingerprint` = الـfixtures + عددها + الـmode + hash الـscorer + **نسخة جدول المعايرة**
+ نسخة المخطط + إعدادات التجربة. **كود المصنف ليس فيه عمدًا** — تغييره هو ما تقيسه المقارنة، ورفضها لأجله
يجعل التقرير بلا معنى. hashes المصنف تُسجَّل بجانب التقرير للإسناد، لا للمنع.

| baseline | النتيجة |
| :-- | :-- |
| بصمة مطابقة | يقارن؛ delta لكل شيء |
| `mode: live` + `userPlan: ultra` (سيناريو المراجعة) | **يُحجب** — `NOT COMPARABLE — mode: live → offline \| experiment.userPlan: ultra → free` |
| `scorerSha256` مختلف | **يُحجب** — تغيّر المسطرة |
| `fixtureSha256` أو `caseCount` أو `calibrationVersion` أو `schemaVersion` مختلف | **يُحجب** |
| hashes المصنف مختلفة | **يقارن** — وهذا هو الغرض |

### 5.3 المقارنة الكاملة (R7)

`headline` و`splits.dev` و`splits.frozen` و`categoryDelta` و`decisions.countsDelta`
و`baselineBreakdown` و`baselineAutoSaveSafety` و`baselineDerivedLlmRoutes`.
**ثبات المتوسط لم يعد قادرًا على إخفاء تراجع فئة.**

مثال اصطناعي كامل في `example-baseline.json` و`example-comparison.json`:

## 6. R5، R6 — التعريفات والعدّ

### R5: مقياسان، لا واحد

المراجعة محقّة: النص قال «أي scoring failure» والعدّاد كان `SystemMetrics.unsafeAutoSaves`،
وهو يفحص المبلغ/الاتجاه/الفئة/العدد فقط.

| الحقل | يعدّ | على الـcorpus الحالي |
| :-- | :-- | --: |
| `tripleUnsafeAutoSaveCases` | auto_save بمبلغ/اتجاه/فئة/عدد خاطئ | **4** من 85 = 4.71% |
| `autoSaveCasesWithAnyScoredError` | نفسها + أخطاء الفرعية | **7** من 85 = 8.24% |

الفرق ثلاثة أخطاء فرعية — حقيقية، وليست بخطورة مبلغ خاطئ. `doesNotCover` يقول صراحةً إن
أيًا منهما **لا يغطي العملة ولا التاريخ ولا صحة الحفظ في DB**.
والتقرير يرفض إصدار حالة يكون فيها الأوسع أصغر من الأضيق.

### R6: صفر مقاس مقابل غير مقاس

`precision = recall = 0` مع دعم موجب ⇒ **F1 = 0**. `null` صار يعني «لا مقام» فقط.
اختباران منفصلان: فئة أُجيبت خطأً بالكامل ⇒ 0؛ فئة لم تُنتَج قط ⇒ precision null.

### `categoryAnyOf` — اصطلاح مسمّى، لا F1 تقليدي

39 حالة في الـcorpus. البسطان مختلفان (`acceptedAsProduced` للـprecision،
`acceptedAsExpected` للـrecall)، لذا الحاصل **ليس F1 تقليديًا**. سُمّي `lenientF1` ووُثّق،
وأُضيف **`strictCategories`**: نفس الحساب على الحالات ذات الفئة الواحدة المقبولة فقط.
لم أعدّل الـscorer ولا التوقعات.

### حدود المحاذاة، مذكورة في التقرير نفسه

الـscorer يحاذي المبالغ المتساوية بالموضع. `definitions.match` يسمّي الحالات الأربع في
الـcorpus الحالي (`BND-006`, `MON-002`, `MON-003`, `FBND-002`)، واختبار `swapped` يثبت أن
تبديل مبلغين متساويين يُقرأ كخطأي فئة لا كإعادة ترتيب.

## 8. R8 — قيد موروث، أعدت إنتاجه ولم أصلحه

`rejected = false` في `financial-event-plan.ts:118` ⇒ بوابات الجودة الخمس **خضراء**،
وخمسة اختبارات في `financial-event-pipeline.test.ts` **حمراء**، والأمر الكامل يفشل.

**التصنيف العادل، كما في المراجعة:** الأمر الكامل يلتقطها، فلا يصح القول إنها تمر من CI.
لكن نجاح **الغلاف وحده** (وهو يشغّل ملف الجودة فقط) لا يعني نجاح حراس النواة.
**العتبات لم أمسّها** — تغييرها لم يكن مصرّحًا.

تصميم المتابعة، مسجَّل ولم يُنفَّذ: مجموعة regression دلالية مستقلة بـminimal pairs وحارس صريح
لكل ظاهرة — النفي، المستقبل، الأسئلة، التصحيح الذاتي، الاسترداد مقابل الإلغاء، الحركة مقابل
الدخل، الأحداث الناقصة، والمبالغ المتساوية. **بيانات جديدة لا تُسمّى holdout إن استُخدمت في التطوير.**

## 11. `npm ci` — كان مكسورًا، وأُصلح لأن النقطة 3 تتوقف عليه

**كان يفشل على main كما هو.** أثبتّه في حاوية Linux نظيفة بعد **نزع سكربتَي G1** من
`package.json`، فالعيب ليس من صنع G1 ولا G1-R:

```
npm error Missing: @capacitor/cli@8.5.1 from lock file
```

`@capacitor/cli` **معلَن في `package.json`** وغائب من `package-lock.json`. خطوة `npm ci`
تسبق كل شيء في **كل** job، فالـworkflow كله لم يكن ليصل إلى خطوة تشغيل واحدة.

في التسليم السابق سجّلتُه ولم أصلحه. **الآن أصلحتُه**، لأن النقطة 3 تتوقف عليه:

| | |
| :-- | :-- |
| التغيير | `npm install --package-lock-only` |
| الأثر | **62 مدخلًا مضافًا، صفر محذوف، 3 معدَّلة** |
| المعدَّلة الثلاثة | جذر الـlock يكتسب `@capacitor/cli` في devDependencies؛ و`readable-stream` و`string_decoder` ينتقلان من `optional` إلى `devOptional` لأنهما صارا قابلَين للوصول من tبعية تطوير |
| **لا إصدار تغيّر** | لا تبعية أُضيفت أو حُذفت أو غُيّر إصدارها |
| التحقق | `npm ci` يخرج **0** في حاوية `node:22-bookworm` نظيفة |

هذا **إصلاح تناقض** بين ملفين، لا تغيير تبعيات: جعلتُ الـlock يوافق `package.json` الذي
كان يعلن الحزمة أصلًا.

## 12. الحدود — ما لا يثبته هذا العمل

- **GitHub Actions:** رُفع الآن إلى `main` فيبدأ فعليًا (§14). قبل الرفع كان الـYAML مُحلَّلًا
  وكل خطوة تنجح محليًا على Windows وعلى Linux في حاوية `node:22-bookworm`؛ **نتيجة التشغيل
  الفعلي على GitHub ليست جزءًا من هذا التقرير** لأنها تحدث بعد الرفع.
- **offline فقط.** لا مزوّد، لا STT، لا شبكة، لا DB. الـtokens صفر **بالبناء**.
- **`derivedLlmRoutes` ليس عدّاد طلبات** — لا يرى retry ولا failover.
- **`frozen` لم تعد holdout مستقلة**؛ استُخدمت في تشخيص regression في جولة النواة.
- **`tripleF1` لا يقيس العملة ولا التاريخ ولا صحة الحفظ.**
- **لم أشغّل** `npm run test` ولا `test:e2e` ولا `build` ولا lint المشروع كله.
- **الأرقام لم تتحسّن ولا تراجعت.** G1-R لم يلمس المصنف؛ أي حديث عن دقة هنا هو عن الـcorpus
  الاصطناعي المحلي، لا عن صوت مصري واقعي.
