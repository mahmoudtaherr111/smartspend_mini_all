## 1. 📖 فكرة المشروع ورؤيته العامة

**SmartSpend AI** هو نظام متكامل (Full-Stack Enterprise Web Application) صُمم خصيصاً لإدارة وتتبع الأمور المالية الشخصية بطريقة فائقة الذكاء والمرونة، وبتركيز كامل على **المستخدم العربي والمصري**. 

### 💡 ما هي المشكلة التي يحلها المشروع؟
معظم تطبيقات تتبع المصاريف التقليدية تتطلب من المستخدم إدخالاً يدوياً مملاً ومكرراً للبيانات (تحديد الفئة، كتابة المبلغ، كتابة الوصف، تحديد التاريخ)، مما يؤدي بالتبعية إلى تكاسل المستخدم وتوقفه عن التتبع. 

يأتي **SmartSpend AI** ليحل هذه المعضلة جذرياً من خلال تقديم واجهة تفاعلية تعتمد على **اللغة الطبيعية (Natural Language Processing)** و**الذكاء الاصطناعي**:
- **الكتابة بالعامية:** يستطيع المستخدم ببساطة كتابة عبارات عامية مصرية مثل *"دفعت 150 جنيه مواصلات وصرفت 300 جنيه غدا في مطعم"* ليقوم النظام فوراً وبلحظة واحدة بتحليل الجملة وتفكيكها إلى عمليات منفصلة وتصنيف كل عملية في فئتها الرئيسية والفرعية وحفظها.
- **التسجيل الصوتي:** يستطيع المستخدم الضغط على زر الميكروفون والتحدث بلهجته الطبيعية لتقوم الواجهة بنسخ الصوت وتحويله إلى معاملات مالية منظمة ومسجلة تلقائياً.
- **التقاط الرسائل البنكية:** يتيح النظام دمجاً فريداً من نوعه مع الهواتف الذكية (iOS Shortcuts / Android APIs) لالتقاط رسائل البنوك الواردة ومحافظ الهاتف (مثل فودافون كاش و إنستاباي) ومحفظة Apple Pay بشكل لحظي وتلقائي بمجرد وصول الرسالة إلى الهاتف وتحليلها وتصنيفها فوراً كدخل أو مصروف دون فتح التطبيق.
- **رؤية ذكية مبنية على البيانات:** بفضل محركات الاستنتاج المالي وسلوك الإنفاق، يعيد التطبيق صياغة الأرقام الجافة على شكل نصائح وتوقعات مخصصة بالعامية المصرية تشبه المحاسب المالي الشخصي الصديق.

## 2. ✨ المميزات الرئيسية للتطبيق

| الميزة | الوصف الفني والعملي |
| :--- | :--- |
| **محرك التصنيف الهجين** | دمج ذكي فائق الكفاءة بين الـ **Rule Engine** المحلي (للعمليات السريعة منخفضة التكلفة) و **Gemini AI** (للعبارات الطويلة والمعقدة). |
| **التسجيل والتحليل الصوتي** | إمكانية إدخال المصاريف والمدخولات عبر التحدث الطبيعي للهاتف مع نسخ وتحليل ذكي فوري. |
| **تلقي الرسائل البنكية و Apple Pay** | تتبع فوري وتلقائي لحسابات البنوك المصرية (الأهلي، مصر، CIB)، ومحافظ الموبايل (InstaPay, Vodafone Cash)، وحركات Apple Pay. |
| **لوحة تحكم ذكاء المستخدم (Intelligence)** | استنتاج مؤشرات الاستقرار المالي (`stable`, `watch`, `pressure`) وأنماط الإنفاق بنماذج ذكاء سلوكي مخصصة. |
| **تقارير مالية مخصصة ومقارنات** | توليد رؤى وتوصيات توفير مالية شهرية وسنوية فريدة لكل مستخدم، مع مقارنات متطورة بين أداء الشهور. |
| **نظام مصادقة مزدوج متكامل** | تسجيل دخول مرن عبر **Google OAuth 2.0** أو عبر **رقم الهاتف المحمول المصري** وكلمة المرور المشفرة بـ `bcrypt`. |
| **نظام اشتراكات متدرج (Subscriptions)** | ثلاث باقات رئيسية (`Free`, `Pro`, `Ultra`) بحدود يومية وشهرية دقيقة واستخدام مختلف لنماذج الذكاء الاصطناعي. |
| **لوحة تحكم إدارية شاملة (Admin)** | إدارة المستخدمين، الجلسات النشطة، تذاكر الدعم الفني، حملات الإعلانات، إحصائيات النظام بالكامل وإعدادات AI. |
| **نظام تذاكر الدعم الفني (Support)** | نظام تذاكر دعم متدرج لضمان تقديم مساعدة فورية مع نظام تعيين للتذاكر وتصنيف الحالات. |
| **نظام الإحالات (Referral System)** | توليد تلقائي لأكواد إحالة فريدة للمستخدمين وتتبع الإحالات الناجحة لزيادة تفاعل المستخدمين والنمو. |
| **محرك الإعلانات المدمج (Ads Manager)** | إعلانات ديناميكية في الشريط الجانبي أو البانر أو النوافذ المنبثقة مستهدفة حسب خطة المستخدم مع تتبع الظهور والنقر. |
| **تصدير متطور للبيانات** | تصدير فوري لكل العمليات المالية للمستخدم بصيغ متطورة مثل `XLSX` (Excel)، `CSV`، أو `JSON`. |
| **محرك SEO وديناميكية Sitemap** | تخصيص كامل للـ Meta tags وعناوين الصفحات ديناميكياً مع توليد لحظي لملفات Sitemap XML للأدمن. |

## 3. 🏗️ الهيكل التقني العام (Architecture & Stack)

يتبع التطبيق بنية **Monorepo** منظمة ومبنية بنظام متين يفصل بشكل واضح ومطلق بين الواجهة الأمامية والواجهة الخلفية مع تشارك "العقود والأنواع" لضمان ثبات البيانات (Type-Safety).

```
┌─────────────────────────────────────────────────────────────┐
│                        Client (Browser)                      │
│  React 18 + Vite + Tailwind CSS + shadcn/ui + React Router   │
│         TanStack Query v5 + tRPC Client (Type-Safe HTTP)     │
└──────────────────────────┬──────────────────────────────────┘
                           │ HTTP Requests (/api/trpc)
┌──────────────────────────▼──────────────────────────────────┐
│                      Hono Server (Node.js 20)                │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────────────┐  │
│  │  tRPC Router│  │ Google OAuth│  │  Health & Static    │  │
│  │  (/api/trpc)│  │  (/api/auth)│  │  Endpoints          │  │
│  └─────────────┘  └─────────────┘  └─────────────────────┘  │
│  ┌─────────────────────────────────────────────────────────┐ │
│  │     Middleware Layer (Dual Auth Context, CORS, Logger)  │ │
│  └─────────────────────────────────────────────────────────┘ │
│  ┌─────────────────────────────────────────────────────────┐ │
│  │   20+ Services & Engines (Inference, Personalization...)│ │
│  └─────────────────────────────────────────────────────────┘ │
│  ┌─────────────────────────────────────────────────────────┐ │
│  │   Drizzle ORM Engine + MySQL 8.0 Connection Pool        │ │
│  └─────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────┘
```

### 💻 التقنيات المعتمدة (Technology Stack):
*   **الواجهة الأمامية (Frontend):** React 18، TypeScript 5.7، Vite 7.2، Tailwind CSS v3.4، ومكونات **shadcn/ui** المخصصة (أكثر من 50 مكوناً فاخراً)، بالإضافة للمكتبة الرسومية التفاعلية **Recharts**.
*   **الواجهة الخلفية (Backend):** إطار عمل الويب الفائق السرعة والخفيف **Hono 4** يعمل على بيئة Node.js 20.
*   **طبقة الاتصال والـ API:** بروتوكول **tRPC v11** الذي ينشئ اتصالاً فورياً آمناً ومحمي الأنواع (End-to-End Type-Safety) بين السيرفر والفرونت إند، متكاملاً مع **TanStack Query (React Query) v5** لإدارة التخزين المؤقت (Caching) والطلبات المتزامنة.
*   **طبقة البيانات وقاعدة البيانات:** قاعدة البيانات **MySQL 8** الشهيرة مع استخدام **Drizzle ORM** لكتابة الاستعلامات وبناء العلاقات والـ Schema، بالإضافة للتحقق الصارم من صحة البيانات باستخدام **Zod**.
*   **الذكاء الاصطناعي:** نماذج **Google Generative AI (Gemini 1.5 Flash / Pro / Ultra & Gemma)** للتعرف على اللهجة المصرية وتقديم التحليلات التنبؤية المتطورة.

## 5. 🔍 شرح تفصيلي ومكثف لملفات ومجلدات المشروع

### 📁 `api/` — الخادم الخلفي (Backend Server)
هذا المجلد يحتوي على الكود الكامل للخادم والمنطق الداخلي (Business Logic). يرتكز كلياً على إطار عمل **Hono** الموجه بـ **tRPC** لضمان اتصال آمن وخالٍ من الأخطاء البرمجية.

#### أ. الملفات الأساسية في `api/`:
*   **`boot.ts`:** هو ملف الانطلاق والتشغيل للخلفية، يقوم بإنشاء مثيل خادم Hono، ضبط سياسات أمان CORS، نظام الحفظ والمراقبة (Logger)، ثم تهيئة مسار Google OAuth المباشر ومسار الـ tRPC الأساسي (`/api/trpc`). يعمل الخادم افتراضياً على المنفذ `3000`.
*   **`router.ts`:** الموجه البرمجي الرئيسي لـ tRPC، يستورد كل الـ Routers الفرعية ويجمعها في موجه عملاق مسمى بـ `appRouter` ويقوم بتصدير نوعه `AppRouter` ليتمكن الفرونت إند من استخدامه للوصول لكافة الدوال البرمجية مع تحقق تلقائي من الأنواع بنسبة 100%.
*   **`context.ts`:** من أهم الملفات الأمنية، يقوم بفحص سياق كل طلب شبكة قادم؛ حيث يفحص أولاً الكوكيز بحثاً عن جلسة OAuth (`google_session HttpOnly cookie`)، وإذا لم يجد، يفحص ترويسة الطلب (`Authorization: Bearer <Token>`) للتحقق من المصادقة المحلية ورقم الهاتف، ثم يطابق الـ Session في جدول الجلسات ويعيد بيانات المستخدم الموحدة `UnifiedUser` إلى الـ router.
*   **`middleware.ts`:** يُحدد هذا الملف صلاحيات الوصول للراوترات، حيث يعرف:
    1.  `publicProcedure`: يُسمح لأي زائر باستدعائه (مثل التسجيل والدخول والصفحات العامة).
    2.  `authedProcedure`: يتطلب بالضرورة وجود مستخدم مسجل الدخول وصاحب جلسة نشطة.
    3.  `proProcedure`: يتطلب أن يكون للمستخدم خطة اشتراك فعالة من نوع `pro` أو `ultra` أو أن يكون مديراً (`admin`).
    4.  `moderatorProcedure`: يُسمح به للمراقبين (`moderator`) والمديرين (`admin`).
    5.  `adminProcedure`: لا يمكن استدعاؤه نهائياً إلا من قبل مدير كامل الصلاحيات (`admin`).

#### ب. الـ Routers المتخصصة في `api/`:
*   **`auth-router.ts`:** معالجة تيار مصادقة Google OAuth (توليد الرابط الموجه للمستخدم، التقاط الرد، سحب بيانات العضو من Google، إنشاء سجل جديد في جدول `users` بالـ Role والـ Plan الافتراضية، وإصدار ملف JWT أمني في كوكيز العميل).
*   **`local-auth-router.ts`:** يدير دورة حياة التسجيل والدخول والخروج للعضو المحلي (رقم الهاتف والرقم السري)، مع حماية وإعطاء إحصائيات المستخدم الفردية للأدمن.
*   **`local-auth-utils.ts`:** خوارزميات مساعدة للمصادقة المحلية: توليد التوكنز، تشفير كلمة السر ومطابقتها، التحقق الصارم من أن الهاتف مدخل بالهيئة المصرية الصحيحة (11 رقماً ويبدأ بأرقام فودافون/أورنج/اتصالات/we)، وتوليد كود الإحالة التلقائي.
*   **`expense-router.ts`:** يُعد العمود الفقري للعمليات المالية. يحتوي على دوال CRUD للمصاريف والدخول، ودوال جلب الإحصائيات الشهرية والسنوية المعقدة التي تشمل متوسط الصرف اليومي، أعلى فئة من حيث الصرف، الحركات ذات القيمة الأعلى، حساب المقارنة المئوية مع الشهر السابق، وتدفق الإنفاق اليومي والساعي.
*   **`ai-router.ts`:** يدير الربط التام مع Gemini AI. يستقبل النصوص والصوت، ويوجهها لمحرك التصنيف السريع (Rule Engine) أو يرسلها للـ AI، كما يتعامل مع توليد ملخصات وتوقعات الشهور والسنوات الذكية، ويدير معايير سحب وحساب التوكنز وتخفيض الحد اليومي للـ Free وتسهيل الترقية.
*   **`analytics-router.ts`:** يتيح تسجيل الأحداث الهامة التي يقوم بها المستخدم لمعرفة سلوكه واحتياجاته الاستباقية لتوفير الأموال.
*   **`admin-router.ts`:** لوحة الإدراك الكاملة للمدير، تتيح الاطلاع اللحظي على سلامة النظام، إحصائيات المستخدمين الجدد، تعديل أدوار وباقات المستخدمين، حذف الحسابات بالكامل مع كل الحركات والجلسات التابعة لضمان الخصوصية وسرعة الأداء، وإدارة إعدادات AI والتصنيفات.
*   **`support-router.ts`:** نظام تذاكر الدعم لحل شكاوى المستخدمين بتبادل الرسائل الفورية مع المشرفين.
*   **`export-router.ts`:** محرك التصدير الفوري؛ يعتمد على حزمة `xlsx` لمعالجة البيانات وتحويل حركات العضو في قاعدة البيانات إلى ملف Excel منسق واحترافي أو ملفات نصية كـ CSV/JSON.
*   **`ads-router.ts`:** إدارة كاملة للإعلانات؛ عرضها ديناميكياً بناءً على خطة العضو لضمان عدم إزعاج مستخدمي Pro، وحساب الظهور الفعلي والنقرات لكل إعلان للتحليلات التسويقية للأدمن.
*   **`referral-router.ts`:** معالجة أكواد الإحالات ومكافأة كل من الداعي والمدعو تلقائياً بزيادة مميزات الباقة أو رصيد العمليات.
*   **`seo-router.ts`:** يسمح للأدمن بإدخال وتحديث بيانات الـ Meta Tags لكل صفحة يدوياً، لتوليد ملفات Sitemap حية وصحيحة لأرشفة جوجل.

#### ج. الخدمات المتطورة في `api/services/` (AI Core Engines):
*   **`user-profile-service.ts`:** إنشاء وإدارة بروفايل المستخدم الذكي (`user_profiles`). يجمع بيانات إجابات الـ Onboarding ويحدثها باستمرار مع كل عملية صرف/دخل يقوم بها المستخدم.
*   **`lifestyle-inference-engine.ts`:** محرك خارق يقوم بقراءة سلوك ومعاملات المستخدم المالية واستنتاج تفاصيل حساسة عن نمط حياته: هل العميل متزوج ولديه أطفال؟ هل هو مستأجر لسكن؟ هل يمتلك سيارة؟ ما هو مستوى أمانه المالي؟ يقوم المحرك بحفظ هذه الاستنتاجات لمساعدة النظام في توجيه توصيات ونصائح استثنائية وعالية الدقة والخصوصية للتوفير الفعلي.
*   **`report-personalization-engine.ts`:** يقوم هذا المحرك بصياغة التقارير المخصصة والملخصات الموجهة للمستخدم، مع كتابة نصائح توفير مالية باللهجة المصرية العامية المحببة للمستخدمين، وتكييف النصائح بناءً على حالته المادية المستنتجة.
*   **`adaptive-question-engine.ts`:** محرك الأسئلة التكيفي والذكي في شاشة Onboarding؛ حيث يقوم بتوليد السؤال التالي تلقائياً بالاعتماد الكامل على إجابة السؤال السابق لتجنب إضاعة وقت المستخدم (مثلاً، إذا أجاب العميل بأنه لا يعول أسرة، فلن يتم سؤاله نهائياً عن مصاريف المدارس أو مستلزمات الأطفال).

## 6. 🗄️ هيكل قاعدة البيانات بالتفصيل (Database Schema)

تحتوي قاعدة البيانات على **20 جدولاً متكاملًا** مصممة لتغطية جميع متطلبات النظام والأمان والذكاء السلوكي وتتبع الأنشطة.

### 📊 مخطط العلاقات الرئيسي للجداول الهامة:

```
                  ┌──────────────────────┐
                  │        users         │
                  │  (OAuth Sign-in)     │
                  └──────────┬───────────┘
                             │ (1)
                             │
                             ├───────────────┐
                             │               │ (*)
                    (1)      ▼ (*)           ▼
 ┌───────────────┐ ┌───────────────┐ ┌───────────────┐ ┌───────────────┐
 │ user_profiles │ │   expenses    │ │   sessions    │ │ supportTicket │
 └───────────────┘ └───────────────┘ └───────────────┘ └───────────────┘
         ▲                 ▲                 ▲                 ▲
         │ (1)             │ (*)             │ (*)             │ (*)
         │                 │                 │                 │
         │                 ├───────────────┘                 │
         │                 │                                   │
         │           (1)   ▼ (*)                               │ (*)
 ┌───────┴───────┐ ┌───────────────┐                           │
 │  local_users  │ │  local_users  ├───────────────────────────┘
 │ (Phone Auth)  │ │ (Phone Auth)  │
 └───────────────┘ └───────────────┘
```

### 📋 وصف تفصيلي وتكوين الجداول الرئيسية:

#### 1. جدول مستخدمي جوجل `users`:
يخزن بيانات الأعضاء المسجلين عبر Google OAuth 2.0.
*   `id`: معرف فريد (Primary Key, INT, Auto Increment).
*   `union_id`: معرف جوجل الفريد (VARCHAR, Unique).
*   `name`: الاسم الكامل للمستخدم.
*   `email`: البريد الإلكتروني.
*   `avatar`: رابط الصورة الشخصية.
*   `role`: دور المستخدم في النظام (`user`, `moderator`, `admin`).
*   `plan`: خطة الاشتراك الحالية (`free`, `pro`, `ultra`).
*   `referralCode`: كود إحالة فريد خاص به للتسويق (VARCHAR, Unique).
*   `aiTokensUsed`: عدد التوكنز المستهلكة من قبله بالذكاء الاصطناعي (INT).

#### 2. جدول مستخدمي الهاتف المحمول `local_users`:
يخزن بيانات الأعضاء المسجلين يدوياً برقم هاتف مصري.
*   `id`: معرف فريد (Primary Key, INT, Auto Increment).
*   `name`: اسم المستخدم الكامل.
*   `phone`: رقم هاتف فريد وصحيح الهيئة (VARCHAR, Unique).
*   `password`: كلمة مرور مشفرة بخوارزمية هجين قوية `bcrypt` بطول 60 حرفاً.
*   `role` & `plan`: نفس نظام مستخدمي جوجل لتوحيد الصلاحيات في المحرك.
*   `referralCode`: كود إحالة خاص به للتسويق.

#### 3. جدول المعاملات والعمليات المادية `expenses`:
يخزن كافة حركات الصرف والدخل والتحويلات للجميع.
*   `id`: معرف فريد (Primary Key).
*   `userId`: رقم المستخدم مالك العملية (مرتبط بـ `users` أو `local_users`).
*   `userType`: نوع العميل للتفريق السريع في استعلامات ORM (`oauth` أو `local`).
*   `type`: نوع المعاملة المالية (`income`, `expense`, `transfer`, `investment`).
*   `amount`: قيمة المعاملة المالية بدقة بالغة (Decimal 12,2).
*   `category`: الفئة الرئيسية للعملية (مثل أكل وشرب، مواصلات، فواتير...).
*   `subCategory`: الفئة الفرعية لمزيد من التحليل الدقيق (مثل مطاعم، بقالة، كهرباء...).
*   `rawText`: النص الطبيعي الخام الأصلي الذي أدخله العميل أو جاء بالرسالة البنكية.
*   `source`: مصدر الإدخال (`manual`, `voice`, `ai_parsed`).
*   `date`: تاريخ ووقت حدوث العملية للتحليل الزمني.

#### 4. جدول ذكاء المستخدم وبروفايله `user_profiles`:
يخزن إجابات Onboarding واستنتاجات الذكاء الاصطناعي السلوكية.
*   `id`: معرف فريد مرتبط بالمستخدم.
*   `userId` & `userType`: ربط تام بالعضو.
*   `monthlyIncome`: الدخل الشهري الثابت الفعلي.
*   `financialGoal`: الهدف المالي المباشر (توفير، استثمار، ميزانية، تسديد ديون).
*   `onboardingAnswers`: إجابات الأسئلة التكيفية مخزنة بصيغة `JSON`.
*   `aiInferredAttributes`: الاستنتاجات السلوكية المستنبطة بالـ AI (أطفال، سيارة، سكن...) مخزنة بصيغة `JSON`.

#### 5. جدول سجلات تصنيف الذكاء الاصطناعي `classification_logs`:
سجل تتبع كامل لعمليات الفحص لمراجعة دقة أداء المحرك والـ AI وكلفته.
*   `id`: معرف فريد.
*   `userId`: كود المستخدم.
*   `originalText`: النص الخام قبل التحليل.
*   `parsedBy`: الآلية التي صُنفت بها العبارة (`rule_engine`, `ai`, `hybrid`, `manual`).
*   `finalResult`: البيانات والنتائج النهائية المجمعة بصيغة `JSON`.
*   `confidence`: نسبة دقة وثقة التصنيف (0-100).
*   `modelUsed`: نموذج Gemini المستعمل بالتحديد للفحص.
*   `tokensUsed`: عدد التوكنز التي استهلكتها العملية للفوترة والمحاسبة.

#### 6. باقي الجداول التقنية في النظام:
*   `expense_categories`: فئات مصاريف إضافية ومخصصة ينشئها المستخدم بنفسه.
*   `monthly_reports`: إجماليات وتقارير الشهور المجمعة مسبقاً لسرعة التحميل.
*   `sessions`: جلسات تسجيل الدخول النشطة والتوكنز وأوقات انتهائها ومواقع الأجهزة.

## 7. 🧠 نظام التصنيف الهجين والذكاء الاصطناعي (Hybrid Parser & AI Layer)

يعتمد **SmartSpend AI** على خط أنابيب معالجة فائق الدقة مبني على 7 خطوات متتالية (`classification-pipeline.ts`) لضمان تصنيف المعاملات بسرعة فائقة ودون تكاليف إضافية (Zero-Cost Optimization).

```
Raw Text (العبارة المدخلة)
       │
       ▼
 [Step 1: Normalize Text] ───► توحيد الأرقام والحروف وتنظيف المسافات
       │
       ▼
 [Step 2: Extract Entities] ──► سحب المبالغ والعملة والأسماء بدقة بالغة
       │
       ▼
 [Step 3: Intent Detection] ──► تحديد نوع المعاملة (دخل، مصروف، تحويل، استثمار)
       │
       ▼
 [Step 4: Rule Engine] ───────► البحث في القاموس المصري المحلي وتطابق العبارات
       │
       ├─── (Confidence ≥ 85%) ───► [Auto Save ✅] حفظ فوري سريع وتوفير استخدام AI
       │
       └─── (Confidence < 85%) ───► [Step 5: AI Classifier Layer]
                                           │
                                           ▼
                                    [Gemini 2.5 Flash] ──► (إذا تعطل) ──► [Gemini Fallback]
                                           │
                                           ▼
                               [Step 6: Confidence Scoring]
                                           │
                                           ▼
                               [Step 7: Review Decision]
                                           ├─── (High ≥ 85%) ───────► [Auto Save ✅]
                                           ├─── (Medium 60% - 84%) ──► [Review Screen 📋]
                                           └─── (Low < 60%) ────────► [Smart Clarification ❓]
```

### 📝 أمثلة تفصيلية لكيفية معالجة العبارات المصرية:

1.  **عبارة قصيرة ومباشرة:** *"بنزين 200"*
    *   **محرك القواعد (Rule Engine):** يتعرف فوراً على كلمة `بنزين` المربوطة بـ الفئة الرئيسية `🚗 مواصلات` والفرعية `Fuel` ويستخرج القيمة `200` ونوع العملية `expense`. نسبة الثقة: **95%**.
    *   **القرار:** يُحفظ المصروف فوراً وتلقائياً دون استدعاء الـ AI ودون أي تكلفة مادية!
2.  **عبارة طويلة ومتعددة المعاملات:** *"صرفت 1500 إيجار الشقة وحولت 500 جنيه لأخوي واشترينا أكل بـ 250"*
    *   **محرك القواعد:** يلاحظ طول العبارة ووجود معاملات متعددة، فيقوم فوراً بـتخفيض الثقة وإرسالها للذكاء الاصطناعي مع Prompt متطور ومخصص للعامية المصرية.
    *   **الذكاء الاصطناعي (Gemini):** يقوم بتفكيك العبارة إلى مصفوفة معاملات:
        *   عملية 1: 1500 EGP / سكن (`🏠 سكن`) / إيجار / `expense`.
        *   عملية 2: 500 EGP / مالية (`🏧 مالية`) / تحويل دين / `transfer`.
        *   عملية 3: 250 EGP / أكل وشرب (`🍔 أكل وشرب`) / مطاعم / `expense`.
    *   **القرار:** حفظ العمليات وعرضها منسقة بألوان مريحة للمستخدم لمراجعتها.

## 8. 📲 نظام القراءة التلقائية للرسائل البنكية و Apple Pay (Automated SMS Ingestion)

يوفر **SmartSpend AI** آلية استباقية بالغة الندرة والقيمة، تتيح سحب المعاملات مباشرة فور وصول رسائل المعاملات المادية للهاتف دون تدخل بشري نهائياً.

### 🔌 آلية العمل التفاعلية والربط المالي:
1.  عند إتمام عملية شراء ببطاقة الائتمان، أو إرسال أموال عبر **InstaPay**، أو دفع فاتورة بـ **Vodafone Cash**، أو الدفع السريع بـ **Apple Pay**، تصل رسالة SMS للهاتف بمحتوى العملية.
2.  تقوم أداة الأتمتة المربوطة بالهاتف بالتقاط نص الرسالة وإرساله فوراً عبر طلب POST للـ API الخاص بنا `/api/trpc/ai.parseSMS` محملاً بالـ `Bearer Token` الأمني الخاص بالمستخدم.
3.  يستقبل الـ `Rule Engine` الرسالة ويقوم بتحليلها بفضل قواميس البنوك الضخمة المرفقة بالنظام (يفهم تماماً رسائل بنوك الأهلي، مصر، CIB، QNB، العربي الإفريقي، ومحافظ الهاتف المصرية والرسائل الإنجليزية للعمليات الدولية).
4.  إذا تعقد النص البنكي، يتم الاستعانة بـ Gemini API لاستخلاص البيانات، ثم تقييد العملية كدخل أو مصروف، وتعديل الميزانية والإحصائيات وتدفقات الإنفاق في الـ Dashboard فوراً.

### 📲 دليل الإعداد الفوري والمباشر لمستخدمي الهواتف:

#### 🍏 لمستخدمي آيفون (iOS - Apple Shortcuts):
لقد وفرنا Shortcut جاهزاً ومعداً تماماً لتبسيط الإعداد بضغطة زر واحدة:
1.  ادخل للتطبيق واذهب إلى إعدادات الحساب > قسم **"ربط الآيفون التلقائي (iOS Shortcut)"**.
2.  اضغط على زر **"إنشاء Token"** ثم قم بنسخ التوكن الأمني الفريد المعروض.
3.  اضغط على زر **"Connect iPhone"**؛ سيفتح لك الآيفون رابط تثبيت الـ Shortcut المسمى **SmartSpend Auto Ingest**.
4.  اضغط على **Set Up Shortcut**، وقم بلصق التوكن المنسوخ في خانة المدخل الافتراضي، ثم اضغط حفظ.
5.  الآن، توجه لتطبيق **Shortcuts** في الآيفون > اذهب لعلامة التبويب **Automation** بالأسفل > اضغط إنشاء أتمتة شخصية جديدة (`Create Personal Automation`).
6.  اختر الخيار **Message** (الرسائل).
7.  في حقل **Message Contains** (الرسالة تحتوي على)، اكتب الكلمة المميزة للرسائل البنكية التي ترغب في تتبعها (مثال: `InstaPay` أو `CIB` أو `البنك الأهلي` أو `شراء` أو `خصم`).
8.  تأكد تماماً من اختيار وتفعيل **Run Immediately** (التشغيل فوراً دون سؤالك) لضمان الخصوصية والسرعة الفورية.
9.  اضغط التالي، واختر تشغيل الـ Shortcut الجاهز الذي قمنا بتثبيته مسبقاً.
10. **Apple Pay:** تم تهيئة محرك قواعد النظام تلقائياً لالتقاط حركات محفظة Apple Pay بمجرد وصول رسالة الخصم والـ "Contactless Payment" المصاحبة وحفظها كمصروف لحظياً ومجاناً.

#### 🤖 لمستخدمي أندرويد (Android - MacroDroid / Tasker):
1.  قم بتثبيت تطبيق الأتمتة المفضل مثل **MacroDroid**.
2.  أنشئ Macro جديد؛ واجعل المشغل (`Trigger`) هو: **Incoming SMS** (رسالة واردة) من أرقام البنوك أو المحافظ الخاصة بك.
3.  اضبط الإجراء (`Action`) ليكون: **HTTP POST Request**.
4.  ضع رابط التطبيق الخلفي في خانة الرابط: `https://<YOUR_DOMAIN>/api/trpc/ai.parseSMS`.
5.  أضف الترويسة الأمنية (`Header`): `Authorization: Bearer <YOUR_PERSONAL_TOKEN>`.
6.  أرسل محتوى نص الرسالة كمتغير بصيغة JSON: `{"message": "[sms_body]"}`.

## 9. 🔐 نظام المصادقة والصلاحيات (Dual Auth & RBAC)

يحمي النظام بيانات المستخدمين المالية الصارمة بنظام أمن متعدد المستويات.

### 🔑 المصادقة المزدوجة (Dual Auth):
*   **تسجيل الدخول بـ Google:** يعتمد على بروتوكول `Google OAuth 2.0` بالكامل. يتم تمرير التوكن وتوليد JWT أمني محمي يُخزن في كوكيز العميل المشفرة من نوع `HttpOnly` و `SameSite=Lax` بصلاحية 7 أيام، مما يحمي المستخدم تماماً من هجمات XSS.
*   **تسجيل الدخول المحلي:** للتسجيل برقم الهاتف المصري وكلمة المرور. يتم التحقق من صحة وقانونية الهاتف، وتشفير كلمة السر بـ `bcryptjs` (بمعدل 12 دورة تشفير معقدة)، ويصدر JWT أمني يتم إرساله كتروِيسة `Bearer Token` في كل طلبات tRPC.

### 🛡️ نظام الصلاحيات المتدرج (RBAC):
تتكون صلاحيات النظام من 5 مستويات أمنية مرتبة بتدرج صارم كالتالي:

```
 [1. publicProcedure] ──────► لا يتطلب تسجيل دخول (الlanding والوثائق العامة)
          │
          ▼
 [2. authedProcedure] ──────► يتطلب مستخدم مسجل نشط (user, pro, ultra, moderator, admin)
          │
          ▼
 [3. proProcedure] ─────────► يتطلب ترقية وباقة فعالة (pro, ultra, admin)
          │
          ▼
 [4. moderatorProcedure] ───► يتطلب صلاحيات مراجعة وإشراف (moderator, admin)
          │
          ▼
 [5. adminProcedure] ───────► يتطلب صلاحية الإدارة الكلية والمالك (admin)
```

| الدور الممنوح | الصلاحيات الفنية بالتفصيل |
| :--- | :--- |
| **`user`** (المجاني) | إضافة وتعديل وحذف مصاريفه وجلساته وتذاكره، والتحليل بالصوت والـ AI بحد أقصى **10 طلبات يومية**. |
| **`pro`** | ميزات العضو العادي + استخدام الذكاء الاصطناعي بلا حدود يومية، إخفاء الإعلانات نهائياً، التصدير لملفات Excel، والتقارير المتقدمة. |
| **`ultra`** | ميزات Pro + استخدام حصري لأقوى نماذج Gemini Pro المتقدمة، دعم فني أولي فوري، ودخول كامل لـ Ultra Lounge التفاعلي الفاخر. |
| **`moderator`** | ميزات Pro + الاطلاع الكامل على بيانات الأعضاء، تتبع التذاكر والرد المباشر عليها، وإدارة الجلسات العامة للأمان. |
| **`admin`** (المدير) | تحكم مطلق وكلي بالنظام: تعديل باقات وأدوار الأعضاء، حذف الحسابات، إدارة معلمات AI، تسيير حملات الإعلانات، وإدارة محتوى الـ SEO. |

*   مفاتيح مصادقة **Google OAuth Credentials** (معرف العميل والسر) من منصة Google Cloud Console.

### 🛠️ خطوات التشغيل المحلي بالتفصيل:

#### 1. استنساخ المستودع والدخول للمجلد:
```bash
git clone https://github.com/mahmoudtaherr111/smartspend_mini_all.git
cd smartspend_mini_all
```

#### 2. تثبيت الحزم والاعتماديات:
```bash
npm install
```

```bash
mysql -u root -p < scripts/create_local_db.sql
```

#### 4. تهيئة متغيرات البيئة (.env):
قم بأخذ نسخة من ملف الأمثلة الافتراضي وأنشئ ملفاً جديداً باسم `.env` في جذر المشروع الأساسي:
```bash
cp .env.example .env
```
افتح ملف `.env` وقم بملء المتغيرات بالقيم الصحيحة الخاصة بك:
```env
# رابط قاعدة البيانات MySQL المعتمد للاتصال بـ Drizzle
DATABASE_URL=mysql://root:password@127.0.0.1:3306/smartspend

# إعدادات مفاتيح Google OAuth للتسجيل
GOOGLE_CLIENT_ID=your_google_client_id_here.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=GOCSPX-your_google_client_secret_here
GOOGLE_REDIRECT_URI=http://localhost:3000/api/auth/google/callback

# المفتاح الأمني الخاص بتوقيع JWT في النظام (اختر كلمة سر صعبة جداً)
JWT_SECRET=your_super_high_secure_jwt_secret_key_here

# مفتاح Gemini AI للتحليل الذكي والتصنيف
GEMINI_API_KEY=AIzaSyYourGeminiApiKeyHere

# الموديلات الافتراضية للذكاء الاصطناعي في النظام
GEMINI_MODEL_DEFAULT=gemini-1.5-flash
GEMINI_MODEL_PRO=gemini-1.5-pro
```
